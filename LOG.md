# Lattice — project log

A personal-use, macOS-first, TablePlus-style database client in Rust (Tauri v2 + TypeScript/Tailwind).

## 2026-10-14
- Project named **Lattice**. Architecture reviewed by Fable (async-trait `Driver`/`Connection`, paged results kept in Rust, workspace of per-driver crates).
- `rea-agents` evaluated and not used: TablePlus is a native app (not Electron), and I'm not decompiling it. Behavior and shortcuts are recreated from the public UI and docs; all code is original.
- Step 1: workspace, `dbcore`, `driver-sqlite` (with test).
- Feature survey of installed TablePlus (bundle metadata only, no code copied): drivers = SQLite, LibSQL, Cloudflare D1, DuckDB, PostgreSQL, CockroachDB, Greenplum, Redshift, Vertica, MySQL, MariaDB, MSSQL, Oracle, BigQuery, Snowflake, ClickHouse, MongoDB, Redis, Cassandra, DynamoDB, ElasticSearch. Windows/features: connection groups, SSH tunnel, table structure, filter rules, ER diagram, backup/restore, export, command log, AI chat. Roadmap follows this list.
- Step 2: Tauri v2 shell (`src-tauri`) + Vite/TS/Tailwind UI (`ui`). Unlimited tabs (no cap), CodeMirror 6 editor, virtualized grid that pages rows from Rust (`run_query` + `get_rows`, 200k row cap), object sidebar, ⌘P quick open.
- Shortcuts so far: ⌘T new tab, ⌘W close, ⌘1–9 select tab, ⌘⇧[ / ⌘⇧] prev/next, ⌘Enter run (selection or all), ⌘R reload, ⌘P open quickly, ⌘O / ⌘N connections, ⌘L focus search, ⌘I format SQL.
- Step 3: drivers `driver-postgres` (also CockroachDB/Redshift/Greenplum), `driver-mysql` (also MariaDB). Connection manager UI with saved profiles (JSON in app config dir, passwords in macOS Keychain), Test/Save/Connect. Schema-aware autocomplete per dialect via `schema_map`.
- Known gaps: no TLS for Postgres (NoTls) or SSH tunnel yet; no cancel; results are read-only; UI not visually verified (no screen-capture permission in this session); only the SQLite driver has a test.
- Next: row editing with generated SQL preview, EXPLAIN visualization + lint-based optimizer, visual query builder, TLS/SSH, MSSQL/Redis/Mongo.
- Step 4: DataGrip-inspired completion (`ui/src/complete.ts`): tables after FROM/JOIN/INTO/UPDATE, `alias.` → columns, columns from tables in the statement for SELECT/WHERE/GROUP/ORDER (alias-qualified when several tables), suggested JOIN ON conditions (same-name / `<table>_id` → `id`), functions, keywords, snippets (`sel`, `selc`, `ins`, `upd`, `del`, `grp`), usage-based ranking persisted in localStorage.
- Memory goal (light footprint): release profile (opt-level s, LTO, strip, panic=abort), Tokio capped to 2 workers, `sql-formatter` lazy-loaded, rows paged from Rust and released on tab close, schema map holds names only. Release .app = 8 MB. Idle RSS of main process ≈ 97 MB (`ps`, one run, idle with connection dialog open); WebKit helper processes are separate and not isolated in this measurement — needs a proper profile.
- Step 5: query optimizer + plan visualization. `Connection::explain` returns a dialect-neutral `PlanNode` tree: SQLite (`EXPLAIN QUERY PLAN`, tested), Postgres (`EXPLAIN (FORMAT JSON)`, `ANALYZE` with ⌘⇧E), MySQL (tabular EXPLAIN as a flat chain). UI: ⌘E shows the plan tree (bars = share of time/cost/rows) plus suggestions; `ui/src/lint.ts` has static SQL rules (UPDATE/DELETE without WHERE, SELECT *, leading-wildcard LIKE, function on column, NOT IN subquery, cross join, big OFFSET, ORDER BY without LIMIT, DISTINCT+JOIN, OR across columns, correlated subquery) and plan rules (large full scans, estimate-vs-actual mismatch, temp sort). Postgres/MySQL explain paths are untested against live servers.
- Step 6: row editing in table tabs. Double-click a cell to edit (type `NULL` for null), ⌘I / "+ Row" insert, ⌘⌫ / "− Row" mark delete, ⌘S review & commit. Edits are staged client-side (amber = edited, green = new, red = deleted); `dbcore::build_dml` generates dialect SQL shown in a review dialog, then `execute_batch` runs it in one transaction and rolls back if any UPDATE/DELETE doesn't affect exactly one row (tested on SQLite). Tables/views without a primary key are read-only. MySQL uses a real transaction on one connection and backslash-aware literals. UI flow not exercised in a running app (no screen access).
- Step 7: macOS installer. `scripts/build-dmg.sh` builds a universal (arm64 + x86_64) `Lattice_0.1.0_universal.dmg` (7.3 MB, verified valid, contains Lattice.app + Applications link). Needs `CI=true` so the bundler skips Finder scripting. App is ad-hoc signed only (no Developer ID / notarization), so Gatekeeper will block the first launch: right-click → Open, or `xattr -dr com.apple.quarantine /Applications/Lattice.app`.
